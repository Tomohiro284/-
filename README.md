# 対義語ほんやく

入力した単語や文章を、**まるごと対義語に置き換える**翻訳サイトです。
そのまま残したい語句は、変換する前に選んでおけます。

```
今日はとても暑いので、大きい氷をたくさん買いました。
        ↓
今日は全然寒いので、小さい氷を少し売りました。
```

## 使い方

`index.html` をブラウザで開くだけです。ビルドもサーバーも必要ありません。

```sh
# ローカルで確認する場合
python3 -m http.server 8000
# → http://localhost:8000/
```

インターネットへの公開手順は「[インターネットに公開する](#インターネットに公開する)」を参照してください。

## 画面の流れ

| 手順 | 内容 |
| --- | --- |
| ① 原文を入力 | 単語でも文章でも、複数行でも構いません。入力しながらリアルタイムに変換されます。 |
| ② そのまま残す語句を選ぶ | 入力文から見つかった「変換される語」がチップで並びます。クリックすると **そのまま** に切り替わり、その語は変換されません。 |
| ③ 変換結果 | 変換した語は紫、そのまま残した語は緑で色分けされます。ボタンひとつでコピーできます。 |

### そのまま残す指定の方法は 3 つ

1. **候補チップをクリック** — 入力文の中から自動で見つかった語を、ひとつずつ切り替える
2. **自分で指定** — 単語でも文章でも登録できる（例: `好きな食べ物は大きいケーキです` をまるごと保護）
3. **自動除外** — URL・メールアドレス・`` `コード` ``・#タグ・@ユーザー名は既定で変換しない

指定内容と入力文はブラウザの `localStorage` に保存され、次に開いたときも残ります。
サーバーには何も送信されません。

## 変換のしくみ

辞書ベースの最長一致で置換します。形態素解析器は使いません。

- **活用の展開** (`src/conjugate.js`)
  辞書には終止形だけを登録し、そこから活用形を機械的に生成して索引に入れます。
  イ形容詞（`大きい → 大きく / 大きかった / 大きすぎ …`）、
  五段・一段動詞（`買う → 買いました / 買って`、音便も対応）、
  英語の複数形・三単現・過去形・比較級（`stop → stopped`、`big → bigger`）。
  変換元と変換先で活用の種類が違っても対応します（`増える`(一段) → `減る`(五段)）。

- **誤変換を減らす工夫** (`src/converter.js`)
  - 一文字の漢字（`上`・`前` など）は、前後が漢字なら一致させない
    → `上手` `上野` はそのまま、`上を見る` は `下を見る`
  - 二文字以下の仮名（`はい` など）は、後ろに平仮名が続くなら語の途中とみなす
    → `今日はいい天気` を `今日は悪い天気` に（`はい` を拾わない）
  - 可能形・使役形は辞書の見出し語より後に登録する
    → `開ける` は「`開く` の可能形」ではなく動詞 `開ける` として扱う
  - 保護範囲に少しでも重なる語は変換しない

## インターネットに公開する

**公開先: https://tomohiro284.github.io/-/**

`main` に push すると、`.github/workflows/pages.yml` がテストを走らせたうえで
`gh-pages` ブランチへ成果物を push し、GitHub Pages がそれを配信します。
設定画面での操作は不要です（`gh-pages` ブランチの存在で Pages が有効になります）。

> **なぜ Actions の Pages デプロイを使わないのか**
> `actions/deploy-pages` を使うには先に Pages サイトが作成されている必要がありますが、
> その作成 API は `GITHUB_TOKEN` では叩けません（`Resource not accessible by integration`）。
> ブランチ push 方式ならトークンの `contents: write` だけで完結します。

### 公開URLを変えるとき

独自ドメインを使う場合など、URL を変えたら 2 か所を書き換えます。

```sh
OLD="https://tomohiro284.github.io/-/"
NEW="https://example.com/"
sed -i "s|$OLD|$NEW|g" src/site-config.js *.html robots.txt sitemap.xml
```

独自ドメインは GitHub の **Settings → Pages → Custom domain** で設定し、
DNS 側に CNAME レコードを追加します。

## 広告を掲載する（収益化）

広告枠は最初から用意してあります。`src/site-config.js` の `adsense.client` が
空のあいだは**広告枠ごと非表示**になるので、審査前でもレイアウトは崩れません。

### 手順

1. **先にサイトを公開する** — 審査には稼働中のURLが必要です
2. [Google AdSense](https://adsense.google.com/) に申し込み、サイトを追加する
3. AdSense から渡される確認コードを設置する
   → `src/site-config.js` の `adsense.client` に `ca-pub-...` を入れるだけで、
     全ページに読み込みタグが入ります
4. 審査に通ったら **ads.txt** を有効化する
   → `ads.txt` のコメントを外し、自分のパブリッシャーIDに置き換える
5. AdSense で「ディスプレイ広告」を 2 つ作り、スロットIDを設定に入れる

```js
adsense: {
  client: 'ca-pub-1234567890123456',
  slots: {
    content: '1234567890', // 記事の途中
    footer:  '0987654321', // ページ下部
  },
},
```

広告枠の位置は各 HTML の以下のタグです。増やしたいときはこれをコピーします。

```html
<div class="ad-slot" data-ad-slot="content"></div>
```

### 審査について

AdSense は「独自の価値あるコンテンツ」を求めます。ツール1ページだけのサイトは
**「価値の低い広告枠（コンテンツが不十分）」で不承認になりやすい**点に注意してください。
本リポジトリでは対策として、審査で確認されやすい次のページを用意してあります。

| 用意済み | 内容 |
| --- | --- |
| プライバシーポリシー | Cookie・第三者配信広告についての記載を含む |
| 利用規約 | 利用条件・禁止事項・免責事項 |
| お問い合わせ | 連絡先の明示 |
| このサイトについて | 運営者情報 |
| 使い方 | 読み物としての本文コンテンツ |
| 対義語とは | 対義語の3分類を解説した記事 |
| 対義語一覧 | 辞書から生成した472組の一覧（`index.html?text=...` で各語をツールに送れる） |

そのうえで、**`src/site-config.js` の `owner` と `email` を必ず実在の値に更新してください**
（未設定のままだと運営者情報が空になり、審査で不利になります）。

記事をさらに増やすと承認率と検索流入の両方に効きます。既存ページをコピーして
`<main class="page">` の中身を差し替え、`sitemap.xml` とヘッダーのナビに追加してください。
ヘッダー・フッターの markup は各 HTML に直接書かれているので、変更時は全ページを置換します。

## 辞書を増やす

`src/dictionary.js` の配列に 1 行足すだけです。

```js
// 名詞・形容動詞など
['成功', '失敗', '状態'],

// イ形容詞（活用形は自動生成）
['大きい', '小さい'],

// 動詞（v1 = 一段、v5 = 五段）
['増える', 'v1', '減る', 'v5'],

// 英語（pl = 複数形、v = 動詞活用、adj = 比較級を生成）
['big', 'small', { adj: true }],
```

熟語の一部に紛れ込みやすい語は、4 番目に `true` を渡すと前後の字種を見てから
一致するようになります（一文字の語は自動でこの扱いになります）。

## テスト

```sh
node tests/run.js
```

## 注意

辞書ベースの簡易的な変換なので、文脈によっては不自然な結果になります。
うまくいかない語は、②で「そのまま」に切り替えてお使いください。
