# シードとサンプリングの設定

「同じシードなら必ず同じ絵が出る（正確）」と「破綻せず綺麗に出る」を両立させるための設定です。
この2つは別の話なので、分けて説明します。

---

## 1. シードを正確に再現させる

### まず実測する

設定を信じる前に、実際に同じ絵が出るか確かめてください。WebUI を `--api` 付きで
起動した状態で実行します（このキットの起動スクリプトは既定で有効）。

```bash
python tools/verify_seed.py
```

同じシードで2回、違うシードで1回生成し、ピクセル単位で比較します。

```
合格  再現性: 同一シードで完全に同じ画像になる
合格  健全性: 異なるシードでは異なる画像になる
合格  バッチ整合性: batch_size を変えても結果が変わらない
```

3つ目の「バッチ整合性」は見落とされがちですが重要です。**バッチ枚数を変えただけで
同じシードの絵が変わる**現象が一部のサンプラーで起きます。単発でテストした絵を
あとからまとめ生成しようとして再現しない、という事故の原因になります。

> `pip install Pillow` を入れておくとピクセル単位で比較します。無い場合は
> ファイル全体のハッシュ比較になり、判定が厳しめに出ます。

### 何を固定しているか

| 設定 | 値 | 固定する理由 |
|---|---|---|
| `randn_source` | `CPU` | GPUの乱数は機種依存。CPUにすると**別のPCでも同じ絵**になる |
| `eta_noise_seed_delta` | `0` | シードに定数を足す旧仕様の互換設定。0以外だと絵がずれる |
| `s_churn` | `0.0` | **0より大きいとサンプリング中に追加のノイズが入り、決定性が壊れる** |
| `eta_ddim` | `0.0` | DDIM系を決定的モードで動かす |
| `s_noise` / `s_tmin` / `s_tmax` | `1.0` / `0` / `0` | ノイズ注入量。既定値を明示保存して更新時の変化を防ぐ |
| `sigma_min` / `sigma_max` / `rho` | `0.0` | 0 は「モデル既定に従う」の意味。明示しないと将来の更新で変わりうる |
| `no_dpmpp_sde_batch_determinism` | `true` | SDE系サンプラーのバッチ内ばらつきを抑える |
| `always_discard_next_to_last_sigma` | `false` | ノイズスケジュールの末尾処理。切り替えると絵が変わる |
| `uni_pc_*` | 既定値を明示 | UniPC の内部設定 |

**「既定値と同じ値をわざわざ書く」ことに意味があります。** WebUI を更新したときに
既定値が変わると、過去に保存したシードが再現しなくなるためです。明示保存しておけば
更新の影響を受けません。

起動オプション側では `--opt-sdp-no-mem-attention` を使っています。`--xformers` は
高速ですが**計算順序が非決定的**で、同じシードでも微妙に絵が変わります。

### それでも再現しないとき

`verify_seed.py` が不合格を出した場合、原因はほぼこの3つです。

1. `--xformers` が付いている → 外す
2. `randn_source` が `GPU` のまま → `CPU` にする
3. `s_churn` が 0 でない → 0 にする

### シードを他人と共有する / あとで再現する

生成した PNG にはパラメータが埋め込まれています（`enable_pnginfo: true`）。
WebUI の **PNG Info** タブに画像をドロップすると、シードを含む全設定を復元できます。

ただし**モデルとVAEが同じでなければ再現しません**。シードは「同じモデルに対する
同じ乱数」でしかないためです。共有するときはモデル名とVAE名も併せて伝えてください。

## 2. 綺麗に出すためのサンプリング設定

モデル系統ごとに適正値がまったく違います。プリセットで切り替えてください。

```bash
python tools/apply_config.py --webui-dir "C:\sd\webui" --preset sdxl
python tools/apply_config.py --webui-dir "C:\sd\webui" --preset sd15
python tools/apply_config.py --webui-dir "C:\sd\webui" --preset flux-schnell
```

| | SDXL | SD 1.5 | FLUX.1 schnell |
|---|---|---|---|
| サンプラー | DPM++ 2M | DPM++ 2M | Euler |
| スケジュール | Karras | Karras | Simple |
| ステップ | 30 | 28 | **4** |
| CFG Scale | 5.0 | 7.0 | **1.0（固定）** |
| 解像度 | 1024×1024 | 512×768 | 1024×1024 |
| Hires denoise | 0.4 | 0.4 | 0.35 |
| VAE | sdxl-vae-fp16-fix | vae-ft-mse-840000 | 内蔵 |

**FLUX.1 schnell は他と作法が違います。** 蒸留モデルなので CFG を上げると即座に
破綻します。1.0 から動かさないでください。ステップも4で完成しており、増やしても
綺麗になりません（プリセットでは上限8に制限しています）。

### サンプラーの選び方

| サンプラー | 決定性 | 用途 |
|---|---|---|
| **DPM++ 2M + Karras** | ○ | **既定。迷ったらこれ。**速度・品質・再現性のバランスが最良 |
| DPM++ 2M SDE + Karras | △ | ディテールが出るがバッチでばらつく。決定性が要るなら避ける |
| Euler a | × | 毎回わずかに変わる（ancestral系は仕様上ノイズを足し続ける） |
| Euler | ○ | 素直。FLUX系ではこれ |
| DDIM | ○ | 古い。SD1.5の一部モデルで指定されていることがある |
| UniPC | ○ | 低ステップで速いが好みが分かれる |

**「a」が付くサンプラー（Euler a, DPM++ 2S a など）は避けてください。** ancestral系は
ステップごとにノイズを追加する仕組みで、ステップ数を変えると絵が別物になり、
再現性も低くなります。

### ステップ数

増やせば綺麗になるわけではありません。DPM++ 2M は 25〜30 で収束し、**それ以上は
時間が延びるだけ**です。逆に 15 以下だとざらつきが残ります。

プリセットでは UI 側の入力範囲自体を制限してあるので、事故値を入力できません。

### CFG Scale

「プロンプトに強く従わせたい」と上げがちですが、上げすぎると輪郭が焦げ、
極彩色になり、線が二重になります。

| モデル | 適正 | 破綻し始める値 |
|---|---|---|
| SDXL | 4〜7 | 9以上 |
| SD 1.5 | 5〜8 | 12以上 |
| FLUX schnell | 1.0 のみ | 1.0を超えた時点 |

プロンプトが効かないと感じたときは、CFGを上げるのではなく**プロンプトの語順を変える**
（重要な語を前に置く）方が効果的です。

### Hires.fix（高解像度化）

そのまま大きいサイズで生成すると人物が増殖します。低解像度で生成してから
拡大するのが正解です。

```
Upscaler          : R-ESRGAN 4x+   （同梱・BSD-3-Clause）
Upscale by        : 1.5 〜 2.0
Hires steps       : 14 〜 15
Denoising strength: 0.35 〜 0.5   ← ここが最重要
```

Denoising strength を 0.7 などにすると**別の絵が描き直され**、元の構図が失われます。
0.4 前後が「ディテールは足すが構図は保つ」範囲です。

---

## 3. 品質を上げる順番

設定をいじる前に、効果の大きい順に試してください。

1. **モデルを変える** — 影響が最も大きい。サンプラー調整の何倍も効きます
2. **解像度をモデルの学習解像度に合わせる** — SDXLで512×512を生成すると必ず崩れます
3. **ネガティブプロンプトを入れる** — 推奨設定に投入済み
4. **Hires.fix を使う** — 解像度不足由来の崩れが一気に減ります
5. **CFGとステップを微調整** — ここは最後。効果は小さい

サンプラーを次々に変えて回るより、上の1〜4を先に見直す方が確実に良くなります。
