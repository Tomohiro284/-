# ノイズ・文字化け・バグの原因と対処

症状から逆引きしてください。ほぼすべて**原因が特定されている既知の現象**で、
設定で確定的に潰せます。

---

## 1. ノイズ（画像が壊れる）

### 1-1. 全面がカラーノイズ / 真っ黒 / 真緑になる

**最頻原因: fp16（半精度）演算の破綻。** GTX 1650/1660（Turing の一部）は
半精度の挙動が壊れており、途中で NaN が発生して画像全体が死にます。

```
起動オプション [B] を使う:
--precision full --no-half --no-half-vae
```

`tools/doctor.py` がこれを**実測で検出**します（fp16 行列積が NaN を返すか試す）。
「fp16 演算の健全性チェック 合格」が出ていれば、このGPUではこの原因は除外できます。

> `--disable-nan-check` は**使わないでください**。NaN の検出を止めるだけで、
> 壊れた画像がエラーなしで出力されるようになるだけです。

### 1-2. 画像の一部に紫・黄色の斑点、色があせる

**原因: VAE の不一致または破綻。**

| 使用モデル | 入れるべき VAE |
|---|---|
| SDXL 系 | `sdxl-vae-fp16-fix` |
| SD 1.5 系 | `vae-ft-mse-840000-ema-pruned` |

加えて `--no-half-vae` を必ず付けてください（推奨設定では全プリセットに入れてあります）。
SDXL に SD1.5 用 VAE を当てると**全面ノイズ**になります。組み合わせを間違えないこと。

### 1-3. 輪郭が焦げる、極彩色になる、線が二重になる

**原因: CFG Scale が高すぎる。** 「プロンプトに強く従わせたい」と上げがちですが、
上げすぎると破綻します。

| モデル | 適正 CFG |
|---|---|
| SDXL | **4.0 〜 7.0**（推奨 5.0） |
| SD 1.5 | 5.0 〜 8.0（推奨 7.0） |
| FLUX.1 schnell | 1.0（distilled のため上げてはいけない） |

推奨設定では UI の上限を 9.0 に制限してあり、事故値を入力できません。

### 1-4. ざらつきが残る、ディテールが溶ける

**原因: ステップ数とサンプラーの不整合。**

- `DPM++ 2M` + `Karras` + **30ステップ** を既定にしてあります。ここから動かさないのが安全。
- `DPM++ SDE` 系はステップを増やしても収束しないことがあり、バッチ内で結果がばらつきます。
- ステップ 15 以下はどのサンプラーでも残留ノイズが出ます（FLUX schnell を除く）。

### 1-5. Hires.fix で人物が増殖する / 崩れる

**原因: Denoising strength が高すぎる。** 0.7 などにすると別画像が描き直されます。

```
Denoising strength: 0.35 〜 0.5（推奨 0.4）
Upscale by:         1.5 〜 2.0
Hires steps:        15
```

### 1-6. 生成中のプレビューがノイズだらけ

**これは不具合ではありません。** 拡散モデルはノイズから徐々に画像を作るため、
途中経過がノイズに見えるのは正常です。加えて既定のプレビューは「近似デコード」で、
実際より汚く表示されます。

推奨設定では紛らわしさを避けるため**プレビューを無効化**しています
（`live_previews_enable: false`）。表示したい場合は
`show_progress_type` を `Full` にすると正確なプレビューになります（少し遅くなります）。

## 2. 文字化け

「文字化け」は2種類あり、原因がまったく違います。

### 2-1. 画像の中の文字がデタラメになる

**原因: モデルの能力上の限界であって、設定では直りません。**
SD1.5 / SDXL は文字を「文字らしい形の模様」として描くため、読める英単語すら出せません。
日本語はさらに不可能です。

対処は2つだけです。

1. **文字を描けるモデルを使う** — `FLUX.1 [schnell]`（Apache-2.0、商用可）は
   英数字をかなり正確に描けます。許可リストの Tier A に入れてある理由がこれです。
2. **文字を描かせない** — ネガティブプロンプトで抑制する（推奨設定に投入済み）:
   ```
   text, watermark, signature, username, artist name, logo,
   letters, words, caption, subtitles
   ```
   ロゴや看板の文字は、生成後に画像編集ソフトで載せるのが確実です。

日本語の文字を画像内に入れたい場合、現行のどのモデルでも実用品質にはなりません。
後段合成を前提に設計してください。

### 2-2. コンソール・UI・ファイル名が「譁�蟄怜喧縺�」のようになる

**原因: Windows の既定コードページが CP932 のため。** 日本語環境で必発です。

対処（`install/webui-user.bat` に投入済み）:

```bat
chcp 65001 > nul
set PYTHONUTF8=1
set PYTHONIOENCODING=utf-8
```

さらに**出力ファイル名にプロンプトを埋めない**ことが重要です。日本語プロンプトが
ファイル名に入ると、OS 側で化けたり、パス長超過で保存自体が失敗します。

```json
"samples_filename_pattern": "[seed]-[model_name]"
```

`tools/doctor.py` は現在の文字コードとファイル名パターンの両方を検査します。

## 3. バグ（起動しない・落ちる・結果が再現しない）

### 3-1. 起動時にエラーで止まる、拡張機能をいれたら壊れた

**最頻原因: 拡張機能どうしの依存衝突。** 拡張は互いのライブラリバージョンを
上書きし合うため、増やすほど壊れます。

```
--disable-extra-extensions   ← 全拡張を無効にして起動し、切り分ける
```

安定を最優先するなら、拡張機能は**入れない**か、必要な1〜2個に絞ってください。
`doctor.py` は4個以上で警告を出します。

### 3-2. インストール直後から動かない

チェック順:

1. **Python が 3.10.x か** — 3.11/3.12 では依存解決に失敗します
2. **インストール先パスに日本語・空白が無いか** — `C:\Users\山田\...` は**確実に壊れます**。
   `C:\sd\webui` のような半角英数パスへ移動してください
3. **空き容量** — SDXL は1モデル約6.5GB。書き込み途中で容量切れになると
   モデルファイルが壊れ、「ノイズしか出ない」症状になります

3点とも `doctor.py` が自動判定します。

### 3-3. 同じシード・同じ設定なのに毎回違う画像が出る

**原因: 乱数生成器とアテンション実装の非決定性。**

推奨設定で以下を固定済みです。

| 設定 | 値 | 効果 |
|---|---|---|
| `randn_source` | `CPU` | GPU非依存の乱数に。他環境とも結果が一致する |
| `eta_noise_seed_delta` | `0` | シードのずれを防ぐ |
| `no_dpmpp_sde_batch_determinism` | `true` | SDE系のバッチ内ばらつきを抑制 |
| 起動オプション | `--opt-sdp-no-mem-attention` | 決定的なアテンション実装を使う |

`--xformers` は速度が出ますが**非決定的**です。再現性を捨ててよい場合のみ使ってください。

### 3-4. 途中で落ちる / VRAM不足エラー

```
VRAM 4GB以下  : --lowvram
VRAM 6GB以下  : --medvram
```

加えて `sd_checkpoint_cache: 0` でモデルのメモリキャッシュを切ってあります
（複数モデルを切り替えるとメモリを食い潰して落ちるため）。

### 3-5. `.ckpt` を読み込むと警告が出る

`.ckpt` は Python の pickle 形式で、**読み込むだけで任意のコードが実行され得ます**。
必ず `.safetensors` 版を使ってください。`doctor.py` が `.ckpt` の存在を警告します。
`--disable-safe-unpickle` は付けないでください。

## それでも直らないとき

環境をまっさらにして切り分けます。

```bash
# 1. 拡張を全部止めて起動
./webui.sh --disable-extra-extensions

# 2. それでも駄目なら venv を作り直す
rm -rf venv && ./webui.sh

# 3. 環境の状態を確認
python tools/doctor.py --webui-dir .
```

この順で、原因が「拡張」「Python環境」「ハードウェア」のどれかまで必ず絞れます。
